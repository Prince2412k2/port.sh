project netjail
  name   netjail
  mark   netjail
  year   Jul–Aug 2026
  repo   github.com/Prince2412k2/netjail
  tag    Run any command with only its network sandboxed.
  stats  Go · 16,700 LOC · 28 packages · 6,100 lines of tests · threat model · 16k-word manual
  tools  go, linux, nftables, systemd, ssh, docker
  beat   Why not a container
    A container fixes this by giving the process a different filesystem. Then
    you need volume mounts for everything it touches, copies of the binaries it
    runs, and an image to keep up to date. netjail changes the network instead:
    a namespace, a veth pair, and nftables set to drop by default. The
    filesystem is left alone, so the process goes on using your real files,
    your real toolchain and your real $HOME.
  beat   Five layers, and three of them are on the host
    L1 is the namespace's nft output chain at policy drop. L2 redirects 80, 443
    and 53 to the filtering proxy. L3 turns off forwarding on the veth. L4 is a
    host-side guard that drops forwards. L5 is the absence of any masquerade
    rule matching the sandbox subnet. The last three sit outside the namespace,
    so deleting the namespace's own firewall does not open anything.
  beat   It will not start until it has checked
    netjail run does not launch unless containment verifies, and there is no
    override flag. The preflight never reads the rules back. Reading your own
    configuration only proves you wrote it. Instead it opens a real connection
    from inside the namespace and requires that connection to fail.
  beat   The log cannot hold what it must not leak
    Query parameters are stripped before the logging layer sees them. The
    guarantee is structural, not a matter of being careful: internal/events
    imports nothing from net/http, so no type in it can hold a header, a body
    or a raw URL. Events go to XDG_RUNTIME_DIR at mode 0600 on tmpfs. If that
    variable is unset the proxy refuses to start, instead of picking somewhere
    world-writable.

project watch-party
  name   watch-party
  mark   watch-party
  year   Jun–Aug 2026
  repo   private
  tag    Self-hosted movie nights, frame-accurate across devices.
  stats  Dart + TypeScript · ~115k LOC · 471 commits · 152 test files · 11 scenario suites
  tools  dart, flutter, typescript, javascript, webrtc, livekit, jellyfin, sonarr, radarr, qbittorrent
  draft  yes
  beat   One decision core, mirrored in two languages
    The part that decides what a player should do next is pure, and it exists
    twice: once in JavaScript for the web client, once in Dart for the desktop
    app. Two copies drift. Generated JSON conformance vectors run in both CIs
    and hold them equivalent, so a divergence fails a build instead of a movie
    night three weeks later.
  beat   Nobody can read the clock, only estimate it
    Two players agreeing on a timestamp is easy. Agreeing on *now*, across a
    network that lies at random, is the whole problem. Raw offset samples are
    mostly noise with the occasional huge spike. Outliers are rejected, what
    survives is weighted by its own uncertainty, and a Theil-Sen term carries
    the skew. Least squares would chase the spikes. A median of pairwise slopes
    gives each one a single vote.
  beat   The controller only acts on what it can actually see
    Snapping to the right position stutters. Easing toward it drifts. So the
    playback rate runs through a PI controller. Left ungated it chases
    measurement noise it cannot observe, and the rate flutters audibly. Gating
    the error on certainty is the part that made it work. Drift and rate
    flutter are written down as numbers and asserted by a scenario harness.
  beat   A seek gets planned before it gets issued
    A seek costs time, and pretending it does not gives you a chase loop: seek
    to where the other client is, arrive late because the seek took a moment,
    seek again. The cost is modelled and the move runs as a rendezvous, aimed
    at where you will both be.

project logify
  name   logify + coolify_logs
  mark   logify
  year   Mar–Jun 2026
  repo   github.com/Prince2412k2/logify
  tag    Live container logs from a Coolify host, in your terminal.
  stats  Go + Python · 4 tagged releases · CI · Docker Compose · installers for macOS, Linux, Windows
  tools  go, python, fastapi, websockets, docker, nginx, traefikproxy, caddy, coolify
  beat   Two halves of one tool
    coolify_logs is the gateway on the Docker host: a FastAPI service with REST
    and WebSocket endpoints for live container logs, an admin UI for issuing API
    keys, and a browser UI for reading them. logify is the client, a Go TUI that
    browses projects and streams logs. One static binary, with one-line
    installers for macOS, Linux and Windows.
  beat   A key that reads every log reads your credentials too
    Access is scoped per key and per container from the admin UI. A log stream
    is not neutral. It carries whatever the application decided to print, and
    sooner or later that includes something it should not have. Scoping only
    helps if revoking is easy, so it lives in a UI and not a config file.
  beat   WebSockets are where reverse proxies go wrong quietly
    Buffering, idle timeouts and upgrade headers each break a long-lived stream
    in a different way, and none of them log anything useful when they do.
    Coolify, Nginx and Traefik all want different words for the same three
    fixes, so all three are written down. The failure is easy to fix once you
    know which of the four things did it.

project clippy
  name   clippy
  mark   clip
  year   2026
  repo   github.com/Prince2412k2/clip
  tag    Copy on one machine, paste on another — over your own tailnet.
  stats  Go, stdlib only, no cgo · single static binary · spec, plan and design docs
  tools  go, tailscale, linux, docker
  beat   The tailnet is the trust boundary
    There is no application-level auth. That is the design, not an omission.
    Each daemon binds only to the Tailscale interface, never to 0.0.0.0, so
    Tailscale's encryption and ACLs are the boundary. A second home-made one
    beside them would be the weaker of the two. The cost is worth saying out
    loud: anyone on your tailnet can write to your clipboard, so keep the
    tailnet to machines you trust.
  beat   Two invariants, written down before the code
    Content that was received and written to the clipboard is never echoed
    back, or two machines watching each other fill the whole fleet with one
    copy. Identical repeats are deduped by content hash. Both are one sentence
    long and both are unit-tested. They look obvious written down and cost a
    lot to find at runtime.
  beat   One binary, no cgo
    Three operating systems with three unrelated ideas of what a clipboard is,
    and the usual answer is cgo. The standard library alone keeps the single
    static binary, which was the point of the project. The backend is worked
    out at runtime from the environment instead of being picked at build
    time.

project stylized-maps
  name   stylized-maps
  mark   stylized-maps
  year   2026
  repo   github.com/Prince2412k2/stylized-maps
  tag    A custom vector-tile pipeline for stylized maps of India.
  stats  Python + TypeScript + Java · in progress · Docker Compose behind Caddy
  tools  python, typescript, openjdk, planetiler, vectortiles, openapiinitiative, docker, caddy
  draft  yes
  beat   The default profile decides what a map may contain
    Planetiler's stock profile drops administrative boundaries and stops its
    places layer at city level, so a national view turns up with no state
    divisions and no state names. Writing a Java profile is how you stop arguing
    with the pipeline and start specifying it.
  beat   Tiles are a build artifact and a client contract at once
    With no version on the normalized schema, re-running the pipeline quietly
    changes what the renderer is reading, and you see the bug as bad cartography
    instead of as a diff. So the schema is versioned and the API has a spec.
    Coordinate order, zoom bounds and error shapes are all places where
    undocumented ends up meaning wrong.
  beat   The build has to be pausable
    A full run does not fit in the spare capacity of the machine it runs on, so
    the CLI can start, pause and resume, with automatic, full and manual CPU and
    RAM profiles. Otherwise a build that dies at 80% starts again at zero.

project termap
  name   termap
  mark   termap
  year   Aug 2026
  repo   local
  tag    A map you pan around inside a terminal.
  stats  Rust · 5,200 LOC · ratatui, crossterm, flate2 and nothing else · 1.6 GB archive → 19 MB resident
  tools  rust, vectortiles, linux
  beat   Two axes out of one monochrome cell
    A braille cell is 2×4 dots, so an ordinary 160×46 terminal is really a
    320×184 framebuffer. Storing a float coverage and a depth per subpixel,
    instead of an on/off bit, buys two independent axes. Coverage decides which
    dots light. Depth decides how bright they are. A feature can be faint
    because it is thin or faint because it is far, and the two look different.
  beat   Streaming is what removes the ceiling
    Loading features eagerly costs about 220 bytes each and caps out around two
    or three million, which is not enough for a country at street level. Reading
    PMTiles on demand means the archive size stops mattering: 1.6 GB of India
    renders in 19 MB resident. The published crates are async-first and would
    have pulled a runtime into an otherwise synchronous program, so the
    directory format and the slice of MVT that matters are parsed by hand in
    about four hundred lines.
  beat   Throw away what is behind the camera, do not clamp it
    Perspective is the one depth cue a parallel projection cannot produce, and
    it is not free. Anything behind the camera has to go before the divide.
    Clamping it gives it an enormous scale factor and flings it across the frame
    in a radial fan that looks exactly like a clipping bug. It stays switched
    off at wide zooms, where it buys little and risks that.

project noter
  name   Noter
  mark   noter
  year   2026
  repo   github.com/Prince2412k2/Noter
  tag    A terminal notepad that keeps its own history.
  stats  Python · curses + DuckDB · git-backed versioning
  tools  python, curses, duckdb, git
  draft  yes
  beat   The best decision here was to leave something out
    Reimplementing an editor is months of work to end up somewhere worse than
    the one already configured. Shelling out to $EDITOR means the app inherits
    every keybinding, plugin and habit its user already has, for free.
  beat   The history is a commit graph, not a table imitating one
    Every change is committed to git in the background, so the version history
    is real: dated, browsable from inside the app, and still there if the app is
    not. Notes should outlive the program that wrote them.

project gitswitch
  name   gitswitch
  mark   gitswitch
  year   Apr 2026
  repo   github.com/Prince2412k2/gitswitch
  tag    Stop committing with your work email on personal projects.
  stats  Go · v1.0.0 tagged · interactive TUI forms
  tools  go, git, ssh
  beat   Identity and key have to move together
    Profiles live as TOML in ~/.config/git_conf/. Picking one rewrites the
    repository's local .git/config and sets core.sshCommand, so the right key
    pushes the commits the right name is on. Setting them separately is how you
    end up with the correct email and the wrong key.
  beat   Only the local config is touched
    ~/.gitconfig is never touched. Global config cannot say "this repository,
    this person", and a tool that edits it to pretend otherwise leaves you worse
    off than before. The failure is silent and it follows you into the next
    repository.

project vcs
  name   vcs
  mark   vcs
  year   2026
  repo   github.com/Prince2412k2/vcs
  tag    Git, rebuilt from scratch, to find out how it actually works.
  stats  Python · pip-installable · deliberately not for production
  tools  python, git
  beat   Writing the object store is what stops it being magic
    init, commit, log, checkout, merge, reset and cat-file, with a
    content-addressed store underneath and no library doing the hard part. Once
    the name of a thing is its own hash, deduplication and integrity and
    immutability stop being features somebody built and turn into consequences
    you can point at.
  beat   Merge is the one you cannot learn from its output
    Find the common ancestor, diff both sides against it, and admit when the two
    disagree. Writing it turns conflict markers from an annoyance into the only
    sensible answer to a genuinely ambiguous question.

project harbr
  name   harbr
  mark   harbr
  year   2026
  repo   local — not yet published
  tag    A container platform you drive over SSH.
  stats  Rust · 10,900 LOC · 32 modules · russh + bollard + rusqlite · Traefik + ACME · CI
  tools  rust, ssh, docker, traefikproxy, git, linux
  beat   The SSH server is the interface
    There is no web UI and no agent to install. `ssh harbr@your-box` lands you
    in the TUI, and the key you already authenticated with *is* the login. The
    gate names it back to you. The first key to connect claims the instance as
    admin; an unknown one can file an access request, and when an admin approves
    it under Settings the person is in without reconnecting.
  beat   Compose, without the compose CLI
    harbr parses `docker-compose.yml` itself and drives the Docker Engine API
    directly rather than shelling out. Builds go through BuildKit, so
    `--platform=$BUILDPLATFORM`, `RUN --mount=…` and heredocs all work.
    `depends_on: { condition: service_healthy }` is honoured for real, and a
    deployment fails loudly if a service never becomes healthy instead of
    reporting success over a container that is still crash-looping.
  beat   The path has to be the same on both sides
    Compose bind mounts are resolved to absolute paths and handed to the Docker
    daemon, which reads them *on the host*, not inside harbr. So if
    harbr's own data directory were mounted at a different path inside its
    container, every relative bind mount in a user's compose file would point
    somewhere that does not exist. The bundled compose file mounts
    /var/lib/harbr at /var/lib/harbr, and that is load-bearing rather than tidy.
  beat   Rollback is not a rebuild
    Every deployment records the exact image ids it ran. Rolling back re-runs
    those images, so it cannot be defeated by a moving tag, a dependency that
    has since published a new version, or a Dockerfile that no longer builds.
