# models
#
# The agent behind the ask section, in tiers. A tier is a place the questions
# can go; the models inside one are alternatives within it.
#
# Tiers are tried in order and the first that answers is the one sessions use,
# until the next check. Within a tier the models are tried in order too, so a
# tier survives one of its models being withdrawn or rate limited.
#
# Order here is cheapest-to-us first, not best first. Copilot is a seat that is
# already paid for; zen is a free tier on somebody's personal account; the
# cloud models are the backstop that keeps the section alive when the other two
# are out for the day.
#
# Names are opencode's `provider/model`. `opencode models` inside the container
# lists what it can actually reach, and that list moves faster than this file
# does -- trust it over these. Anything unreachable is skipped at the next
# check rather than breaking the section.
#
# Mounted in docker-compose.yml: edit and restart, nothing is compiled in. An
# empty file turns the ask section off, which is the lever to pull if this ever
# gets found by something automated.
#
#
# ANY ACP SERVER
#
# A tier may name the ACP server its models are reached through. Left out, it is
# `opencode acp`, which is what every tier below uses:
#
#   tier  some other agent
#     command  npx -y @zed-industries/claude-code-acp
#     pin      flag --model
#     model    claude-sonnet-4-5
#
# `command` is the program and its arguments, split on whitespace and never
# passed through a shell. `pin` is how the model name reaches it:
#
#   opencode-config   a whole opencode config document in
#                     OPENCODE_CONFIG_CONTENT. The default, and the only one
#                     that also carries the tool policy to the server.
#   flag  --model     appended to the command line, followed by the model name.
#   env   NAME        a named environment variable holding just the model name.
#   none              the server picks for itself.
#
# Naming a `command` that is not opencode switches `pin` to `none` unless a
# `pin` line says otherwise, because handing OPENCODE_CONFIG_CONTENT to
# something else is at best ignored and at worst silently relied upon.
#
# `secrets` lists the credentials that tier's process may see; every other one
# the container carries is removed from its environment before it starts.
# `secrets none` gives it nothing. Separate credential directories are not
# isolation on their own -- without this every agent inherited every token.
#
# What a server may do is NOT set here. That is `portfolio/src/gates.rs`,
# compiled in, and it applies to every server in this file -- adding one cannot
# widen what an agent is allowed to do. Only `opencode-config` pushes the policy
# into the server as well; for everything else the client-side gate is the only
# enforcement, which is what it was always for.

tier  github copilot
  # Copilot's own ACP server rather than opencode's Copilot provider: it is the
  # first-party path to a seat that is already paid for, it takes the model as a
  # flag, and it accepts the gates' allow-list directly.
  #
  # It will not open a session until it has been logged in -- it answers
  # `session/new` with "Authentication required" and advertises `copilot-login`.
  # Either put a fine-grained PAT with "Copilot Requests" in GH_TOKEN, or run
  # `copilot login` once in the container. See deploy/README.md.
  command  copilot --acp
  pin      flag --model
  tools    flag --available-tools
  # Only the GitHub PAT. The provider keys below are stripped from this
  # process's environment before it starts, and its PAT from theirs.
  secrets  GH_TOKEN GITHUB_TOKEN
  # `auto` lets Copilot pick, which is the right default for a seat: the good
  # model on any given week is theirs to know, not ours to pin.
  model  auto

tier  opencode zen
  # Free, and the free tier is a daily allowance rather than a guarantee.
  model  opencode/grok-code
  model  opencode/code-supernova

tier  ollama cloud
  # The backstop. Slower and further away, and still an answer.
  #
  # `ollama-cloud`, not `ollama`: there is no plain `ollama` provider in the
  # registry opencode reads. And the ids carried a `-cloud` suffix, which is how
  # a *local* ollama daemon names the cloud models it proxies -- there is no
  # daemon in this image, so that spelling asked a provider that does not exist
  # for a model that does not exist. This goes straight to ollama.com, which
  # wants OLLAMA_API_KEY. See deploy/README.md.
  model  ollama-cloud/gpt-oss:120b
  model  ollama-cloud/qwen3.5:397b
